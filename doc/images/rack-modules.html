rack.

Shines with
many modules.

  • ✓Dependencies are constructor arguments — the compiler checks them.
  • ✓Started in creation order — list modules in any order, dependencies come first.
  • ✓Optional modules — register them conditionally, read them with moduleOrNull.
  • ✓Forgot one? The app stops at startup and names the module, instead of running on unloaded data.
final settings = SettingsModule();
final auth     = AuthModule(settings);
final notes    = NotesModule(settings, auth);
final sync     = SyncModule(notes, auth);

runApp(RackProvider(
  modules: [sync, notes, auth, settings, // any order
    if (flags.premium) PremiumModule()],    // optional
  builder: () => const App(),
));
STARTS 1Settings→ 2Auth→ 3Notes→ 4Sync
OPTIONAL 
final premium = rack.moduleOrNull<PremiumModule>();
!
FORGOT auth IN THE LIST?
NotesModule.init() failed: AuthModule is used, but no RackProvider provides it, so its init() never ran. Add it to RackProvider.modules.
